# Survey and position papers in arXiv computer science after the 2025 review rule: an interrupted time series

Archived on Zenodo: https://doi.org/10.5281/zenodo.23537739 (this DOI always points to the latest version).

Sean Solano Paul, Independent researcher, Bengaluru, India. Funding: none. Competing interests: none.

## Summary

On 31 October 2025 arXiv announced that review articles and position papers in its computer science (CS) section must have passed peer review before they would be considered. This repository holds the code, derived data, results and figures for an interrupted time series of the monthly share of CS papers that describe themselves as surveys, reviews or position papers, January 2022 to September 2026 (46 months before the rule, 11 after). Papers are harvested as metadata from the arXiv API, classified with fixed keyword rules (frozen before post-policy numbers were computed, version 1.0), and the classifier is validated against 400 hand-labelled papers. The analysis estimates the level change with seasonal terms, same-calendar-month comparisons, placebo dates, precision/recall correction, control categories and a check of peer-review evidence in the metadata.

## How to reproduce

- Python 3.12 (the original runs used 3.12.10 on Windows). Harvesting, parsing, classifying and labelling use only the standard library. The analysis needs `pip install -r requirements.txt` (pinned versions from the original environment).
- Run order (from the repository root; full table in `code/README.md`):
  1. `python code/harvest_api.py days`, then `counts_core`, then `net` (resumable; 5 s between requests; follows the arXiv API Terms of Use)
  2. `python code/parse.py days` and `python code/parse.py net`
  3. `python code/make_label_sample.py` (reproduces the same labelling sample)
  4. label the sheets with `data/labels/RUBRIC.md` (hand labels are in `data/labels/labels.csv`)
  5. `python code/validate.py`, `python code/check_net.py`
  6. `python code/analyze.py` (writes `results/tables`, `results/figures`, `results/analysis_output.md`)
  7. `python code/leave_one_category_out.py` (standard library; reads `results/tables/`; writes `results/leave_one_category_out.csv`, the approximate leave-one-category-out same-month ratios)
  8. Sensitivity checks reported in the paper (saved outputs in `results/`): `python -I code/washout_same_month.py results/tables/monthly_series.csv` (wash-out row of Table 1 and Nov-Dec 2025 spill-over shares; `washout_same_month_output.txt`); `python -I code/alias_numerators.py <repo>` (strict-rule papers listed only under eess.SY or math.NA; `alias_numerators_output.txt`); `python -I code/no_this_perspective.py <repo>` (strict rule without the "this perspective" cue; `no_this_perspective_output.txt`). The last two read `data/net.jsonl.gz` (regenerate with steps 1-2).
- `python code/classify.py` runs the classifier self-tests. Do not edit the rule patterns; a changed classifier should be a new file and reported alongside version 1.0.
- Scripts reference `data/raw/`, `data/net.jsonl.gz` and `data/sources/`, which are regenerated by step 1-2 (see below). Some scripts have D: paths; adjust as needed.

## Not included and why

- The verbatim-from-abstract column of `literature/evidence-table.csv` (third-party abstract text). The arXiv listing data in `data/days.jsonl.gz` keeps abstracts: arXiv metadata is released under CC0.
- Per-paper reading notes on the literature (they contain quotations from copyrighted papers) and the literature gap-analysis note (scoping). The scripts that built the notes are kept; run them on your own copies of the papers.
- `data/net.jsonl.gz` (about 108 MB, over the 50 MB limit) and `data/raw/net/` (about 128 MB of raw API responses). Regenerate with `python code/harvest_api.py net` then `python code/parse.py net`.
- `data/raw/days/` (raw API responses, about 14 MB; the parsed result `data/days.jsonl.gz` is included). Regenerate with `python code/harvest_api.py days`.
- `data/sources/`: saved copies of arXiv web pages, blog posts, the arXiv annual-report PDF and API test files (third-party web content). The URLs are cited in `docs/01-policy-record.md`; `code/html2text.py` and `code/pdf2text.py` convert saved copies to text.
- Literature mapping inputs: full-text PDFs of third-party papers (`bibliometrics/pdfs`, `data/priorwork/pdf`), abstract-bearing master tables and screening stages (`master.csv`, `M.rds`, `stage_*.jsonl`, `evidence_candidates_with_abstracts.csv`), raw API dumps (`bibliometrics/data/raw`), cached citation responses, interactive HTML figures and bundled JS. Regenerate with `literature/python/pipeline.py` and `literature/R/`.
- Scratch and staging copies (`staged-from-E`), virtual environments and caches.
